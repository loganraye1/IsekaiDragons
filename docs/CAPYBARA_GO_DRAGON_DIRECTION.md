# Capybara Go → Isekai Dragons Direction Brief

## What Capybara Go does well

- **Adventure-first structure:** the player pushes a compact route of stops, not an abstract menu grind.
- **Fast combat resolution:** fights are short, readable, and reward-forward.
- **Layered growth:** gear, skills, idle return rewards, and stage progress stack into frequent power bumps.
- **Simple choice cadence:** the player regularly chooses a stop, reward, or build direction without needing a giant rules explanation.
- **Return pressure:** offline/AFK progress and claimable rewards make coming back feel valuable.

## Dragon twist for our game

Isekai Dragons should not be “Capybara Go with a dragon skin.” The differentiator is:

> Short adventure pushes + flashy combat + crunchy dragon evolution identity.

Every run should answer three questions:

1. **Where did my hatchling go?** Adventure route, stop type, scene, enemy, reward.
2. **Why did my dragon win?** ATK/DEF/block/dodge/crit/crit damage/speed, skill trigger, path modifier.
3. **What kind of dragon am I becoming?** Guardian / Raider / Mystic evolution pressure, hoard growth, element identity.

## Current implementation target

The next Fire starter slice should make the Adventure tab itself communicate the plan:

- Capybara lesson being adapted.
- Dragon-specific twist.
- Visible in-game proof already implemented.

This makes the game direction visible to playtesters and gives automation a fixed contract to validate before deeper art/combat work.
